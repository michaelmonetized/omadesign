## Human QA

- Play the supplied Cloud composition and key/apply presets to a pasted image.
- Copy an image and create a new Vector, Pixel, or Layout document using its clipboard dimensions.
- Check complex document thumbnails, then revisit them to exercise the disk cache.
- Continue an agent conversation with its document open and closed. Stop while a closed document is opening.
- Resize an artboard with Scale, Move, Keep, and Clone artwork; undo it. Double-click outside boards on artwork and empty space.
- Export the whole document, a chosen artboard, and a selection. Check preview dimensions, presets, and remembered options after reopening.
- Ask an in-app agent to use a disk photo and edit it in the intended mode.

## Evidence

Native Cargo builds and tests run locally. Site CI is a separate Blacksmith check and is not native build validation.

The complex-motion benchmark in `issue-177-motion-2026-09-30` measures warmed CPU composition at unchanged resolution: median 312.725 ms before and 88.513 ms after (3.53×). These are CPU timings, not measured display FPS; the first uncached frame still pays preparation cost.

Earlier real ACP acceptance exercised all five modes with a disk photograph and completed 26 native edits. See `agent-all-modes-2026-09-30` and `raster-motion-2026-09-30` for those preserved runs.


PR review corrections include first-key rest opacity, raster keyboard nudging and track remapping, whole-layer duplication, explicit aspect-ratio validation, cancellation completion, raster shear and stroke-outline clipboard bounds, guarded legacy preview migration, and artboard modifier/clone behavior. Native acceptance also found and fixed a nested UI-state lock in the new artboard size dialog.

Native dialog acceptance uses real egui pointer/keyboard events and WGPU screenshots. The destination chosen by the host save dialog is supplied by the fixture; the actual export pipeline writes the PNGs and their dimensions/pixels are checked. The source document is compared before and after export. Recording FPS in the JSON describes the capture, not app playback performance.
