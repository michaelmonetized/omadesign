# Motion and 3D scope

MOTION-01 adds bounded numeric expressions, editable nested document compositions, hold and temporal cubic Bezier curves, portable `.omamotion` interchange, nested Lottie precompositions and raster animation output. Expressions preserve keys beneath them. They are a numeric language, not JavaScript: arithmetic, named time/value inputs, numeric functions, seeded randomness and property reads. Export reports named errors; expression evaluation, nested traversal and 3D rasterization accept cancellation. Legacy documents default to no expressions, compositions or 3D scene. Project schema 14 prevents older readers from silently removing these features.

Compositions are ordered above the parent vector/raster artwork. Lottie with interleaved precompositions and parent vector layers is rejected explicitly. Native source timing supports reverse playback, looping and curved time remapping. Lottie expressions are baked at the document frame rate. SVG export explicitly rejects compositions or 3D scenes until those structures can be represented; Lottie rejects model scenes. Native project/motion-project files preserve the editable source data. PNG/APNG/GIF/video use the complete compositor.

MOTION-02 accepts model composition, not general 3D modeling: embedded triangle meshes, hierarchy and transforms, perspective/orthographic cameras, directional/point/spot lights plus ambient illumination, base color, emissive, metallic/roughness, normal and occlusion texture maps, opaque/masked/blended alpha, glTF node animation and skins. CPU rendering uses floating-point linear color and returns a float surface before sRGB encoding. There are no cast shadows or environment maps in this scope.

Import supports glTF 2.0 JSON/GLB, Wavefront OBJ with MTL/textures, ASCII/binary STL, and ASCII/binary FBX 7.x mesh/material hierarchies. glTF cameras/lights/skins and step/linear/cubic node TRS animation remain editable. Unsupported extensions, sparse accessors, morph targets, extra UV sets and vertex colors return errors. FBX animation, deformers and camera/light attributes return errors. No import silently substitutes flattened artwork. External model resources are bounded and resolved inside the model directory, then embedded for source-independent save/reopen.

Import budgets: 64 MiB source/resource, 128 MiB external total, two million vertices/triangles, 16 million texture pixels, 65,536 nodes, 256 texture/resource reads, 128 hierarchy levels. Scene budgets: 32 model objects, 64 manually authored lights and 128 active lights. Render budgets: 16 million output pixels, 250,000 submitted triangles, 100 million triangle samples, two million translucent fragments. Exceeding a limit returns a named error. Nested composition budgets: eight levels, 128 compositions and 32 million visible child-surface pixels per frame. Child surfaces use the exact document-to-viewport transform and are cropped to the visible viewport, without a minimum-scale boost; offscreen compositions allocate no surface. Pure vector virtual canvas dimensions do not impose an area limit. Expression budgets: 4,096 source bytes, 256 expressions, depth 32 and 100,000 charged operations per composition sample. These are explicit limits, not silent truncation.

Qualification uses committed source, focused serialized Rust tests, native project save/reopen, independently decoded PNG output and separately inspected Lottie JSON. It does not establish installed desktop playback, GPU behavior, physical display timing, external 3D editor acceptance or device behavior. No binaries are installed or released by this stream.

Model import/geometry code is adapted from EffectCraft commit `0311bdc34d0dc10c2d18ff7875b4f52d483e5e27` under its MIT option. The required copyright/permission notice is retained at `docs/licenses/effectcraft-model-MIT.txt` and in adapted modules. No additional dependencies or app-version/lockfile changes are required.
