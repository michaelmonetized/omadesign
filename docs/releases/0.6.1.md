Published as [stable/latest v0.6.1](https://github.com/michaelmonetized/omadesign/releases/tag/v0.6.1)
on 2026-09-29. Installed locally using the unmodified public installer.

Release source: `b84c01c99fe249e69b493519b496322ccce4d4d9`.
Source tree: `942ab8312c724e4a8430330980c5f56d303a555b`.

This includes PRs #142, #146, #147, #159–#170: native agent controls and
attachments, offline background removal/upscaling, typography and placement
controls, independent appearance effects, performance work, and release metadata.
The stack was merged in order with its tested ancestry preserved.

## Native validation

- **912 library tests passed, 0 failed, 7 ignored**, plus the all-target check.
  Final 0.6.1 version/embedded-credits validation also passed. The regenerated
  credits retain 417 dependencies and 243 full license/notice texts.
- Font search retains click/typing focus and dismisses correctly. New pixel
  layers preserve selection coordinates, clipping, pending strokes and undo/redo.
- Release review also fixes retouching with differently sized stored masks,
  attachment-heavy History files exceeding the reader's limit, and preview
  failures discarding valid sibling attachments.
- A deterministic cache-admission regression reproduces 79 misses in an
  80-object traversal. Exact bounded request counts retain the expected
  63-object subset. Pixel keys and pixel budgets are unchanged; the additional
  bounded metadata is documented in the [review follow-ups](../qa/fleet-performance-0.6.1/release-review-followups.md).

  toolchain, release optimization, LTO disabled and two Cargo jobs. Both archives
  contain stripped executables, bundled ONNX Runtime 1.28, embedded models,
  licenses, offline documentation and the starter plugin.
- Required glibc versions do not exceed **2.35** for either executable or any
  bundled shared library. ORT also uses standard host C++/GCC runtime libraries;
  these are resolved in the actual-machine installation checks.

## Actual-machine package checks

All application workloads used fresh profiles and network-disabled namespaces.
The archives were installed into isolated prefixes; the installed binaries and
runtime bytes match the archives. Native captures were visually reviewed.

| Machine | Packaged application | Offline AI verification |
| --- | --- | --- |
| m1pro16 / Asahi | Version, inspect, conversion, native GPU capture and saved-document reopening pass | The unmodified installed production UI applies bundled background removal and 2× cutout upscaling. Original pixels, saved mask and canvas placement assertions pass. |
| hpeliteclient / amdgpu | 13/13 package checks pass, including native GPU capture and exact save/reopen metadata | Retained `8ee01b4e` supplemental helpers run real models and automatically load the installed runtime. This verifies package runtime/model compatibility, not current production UI inference. |
| intelpro / i915 | 13/13 package checks pass, including native GPU capture and exact save/reopen metadata | Same explicitly scoped supplemental helper verification. |

Process mappings prove that inference loaded the installed bundled ORT with
runtime overrides unset. The ARM production UI saves a 320×212 background mask,
then saves 640×424 raster/mask data after 2× upscaling while retaining the original
320×212 canvas placement. The actual saved documents reopen and export correctly.

The 1200×900 seed conversion is byte-identical and exactly RGBA-identical across
all three machines, SHA-256
`3cdce7cb10fc90dff5db55b2fc50ad0f7ba28eebc51ec5deab0071c4d3fe08df`.
This narrow package check does not replace the broader benchmark output audit.
Existing remote installs are unchanged. All task-only apps, input helpers and
private compositors exited; cleanup receipts are retained.

## Performance claims

The [paired fleet report](../qa/fleet-performance-0.6.1/README.md) records
**2.87–3.03× faster median brush-drag UI processing** and **3.81–4.56× at p95**
on m1pro16, hpeliteclient and intelpro. Its baseline is issue #158 source
`221834bd`, and its measured candidate is `8ee01b4e`. These are CPU-side UI
durations from two as-used runs per side, not displayed FPS or a comparison with
the shipped 0.6.0 tag. The 108 selected workload runs, slower observations,
output differences and earlier automation failures remain in the report.

The separate [motion comparison](../qa/performance-158/motion.md) retains its
own source identities and 24-document setup. Neither benchmark is relabeled as
a measurement of the final packages after the release-review fixes.
