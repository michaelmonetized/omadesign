# 0.5.3 clipboard hotfix validation

Status: final ARM64 and x86_64 artifacts passed native validation; 0.5.3
is installed locally and published as the latest release. The production
website is deployed and live release/download/installer checks passed.

## Release base and behavior

This release stacks on `3e92620dbd912b40431f12a31316ff13003c6e7a`
(`0.5.2-nightly.1`), including its cloud collaboration work, as Michael
requested. The original dirty Layout checkout at
`/home/michael/Projects/omadesign` is preserved. Implementation is in
`/home/michael/Projects/omadesign-clipboard-0.5.3`, PR #77.

External screenshots, browser image pixels, copied image files, text and
SVG code/files create document layers centered in the visible canvas.
The camera's pan/zoom is respected, including on a second artboard.
Omadesign object copies keep their original world positions. Each paste
is a single undoable edit; existing text editors keep normal insertion.

Omarchy's Alt+V history picker invokes its installed paste helpers, which
send Shift+Insert. The native bridge now accepts that chord on Linux,
including image-only clipboards and residual Alt/Shift modifiers. Ctrl+V,
Command+V (Omarchy's universal Ctrl+V forwarding), dedicated Paste events
and the application's Paste menus use the same native clipboard path.

## Validation

- `cargo test --lib --locked`: **415 passed, 0 failed, 5 ignored**. Ignored tests are the existing optional fixtures.
- `cargo test -p egui-winit --lib --locked clipboard_chord_tests`: **4 passed**.
- `cargo fmt --all --check` and `git diff --check`: passed.
- `cargo clippy --lib --bins --locked`: completed; existing warnings remain in older application/cloud/capture code. The new clipboard modules and native observer have no Clippy diagnostics.
- Regression coverage includes MIME preference, SVG DOCTYPE, file URI decoding, image limits, text/geometry centering, masks/hierarchy, native-size raster persistence, stale internal clipboard rejection, cross-window image/object copies, frame parent ID remapping, atomic undo/redo, destination-tab changes, and focused text editors.
- `src/bin/clipboard_qa.rs` observed real OS key events through the normal native Studio. It did not inject egui events or directly call insertion methods.
- Wayland checks passed for text, PNG, copied file URI, SVG source/file, Command forwarding, installed Omarchy image/text/SVG history helpers, and a real captured screenshot. Residual Alt+Shift+Insert also passed.
- The native fixture had two artboards, camera scale `0.75`, offset `(-900,-120)` and viewport center `(2253.3333,768)`. External content matched that center. Internal raster paste retained its bounds; native Ctrl+Z / Ctrl+Shift+Z and Ctrl+S passed.
- Isolated X11 native checks passed for text, PNG, SVG, local file URIs and empty ownership. A 17 MiB incremental clipboard transfer completed in 549 ms; the previous helper's fixed delay per chunk timed out.
- ARM64 and x86_64 archives build locally with `scripts/release.sh`; both pass the **GLIBC_2.35** ceiling and bundled native codec checks. Final hashes appear below.
- The archive installer was tested under an isolated `--prefix`; executable hashes matched. Packaged ARM64 reopened the saved native paste document in WGPU and wrote a 1200×800 screenshot. x86 native validation passed on `hpeliteclient`; see [the x86 record](0.5.3-x86-validation.md).
