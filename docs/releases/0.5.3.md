## Commands for completion

Run from the 0.5.3 worktree after implementation is complete:

```sh
cargo test --lib --locked
./scripts/release.sh
```

Checksum files name archives relative to `dist`; validate both from there:

```sh
cd dist
sha256sum -c omadesign-0.5.3-aarch64-unknown-linux-gnu.tar.gz.sha256
sha256sum -c omadesign-0.5.3-x86_64-unknown-linux-gnu.tar.gz.sha256
cd ..
./dist/omadesign-0.5.3-aarch64-unknown-linux-gnu/omadesign --version
./dist/omadesign-0.5.3-aarch64-unknown-linux-gnu/install.sh --prefix /tmp/omadesign-0.5.3-install-check
sha256sum dist/omadesign-0.5.3-aarch64-unknown-linux-gnu/omadesign /tmp/omadesign-0.5.3-install-check/bin/omadesign
```

Before installing into the user's home, preserve the accepted binary and
verify its recorded hash. The archive installer atomically replaces the
executable, so an already running process remains on its original build
until relaunched.

Website validation runs from `site`:

```sh
bun install --frozen-lockfile
bun run build
bun run typecheck
```

After local validation, commit and merge the hotfix. Tag the exact validated
commit `v0.5.3`, then create the GitHub release with exactly four assets:
the two `.tar.gz` archives and their `.sha256` files. Record both archive
and executable hashes here. Deploy the website through the existing
site-only Blacksmith `ship.yml` workflow, and verify its completed run and
live output. Do not treat a queued workflow as successful deployment.

The remote installer resolves the latest GitHub release automatically;
`scripts/install-remote.sh` and `site/public/install` require no version pin.
