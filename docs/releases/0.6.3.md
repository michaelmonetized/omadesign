# Omadesign 0.6.3 release validation

Validated locally on 2026-10-01 for [release PR #190](https://github.com/michaelmonetized/omadesign/pull/190). This release implements the nine-item workspace roadmap: motion scrubbing, modifier selection and background opening, file/project menus, drag-to-move and Alt-drag-to-copy, personal templates, a dedicated Typography sidebar, icon tabs, and the centered rainbow mode group.

## Native checks

- **989 library tests passed, 0 failed, 8 ignored**; the final all-target check also passed. Ignored tests require optional external fixtures or explicitly requested workloads.
- **16 native WGPU acceptance checkpoints passed**, using real production UI code, egui pointer/key events, and disposable on-disk documents. These exercise selection, Return/Alt-click background opening, hover scrubbing, copy/move/clone/Trash, reusable templates, project creation, Typography, sidebar icons, Welcome, and Agent. Moving an open document rebases its tab; template reuse opens an unsaved editable copy.
- The motion preview changes 3,961 pixels in the measured thumbnail region between the left and right hover positions. The source document remains unchanged in the library regression.
- File-operation tests cover collision avoidance, all three new document modes, source retention on failure, same-filesystem moves, and cross-filesystem moves with hidden assets and symlinks. Photo paths and undo journals follow project moves. Regression checks also cover symlinked project ancestors, upgrading an unchanged motion index, and immediately paintable project-created Raster documents.
- Credits were regenerated: 417 dependencies and 243 full license/notice texts. The Cargo.lock fingerprint matches.

The [validation receipt](../qa/release-0.6.3/validation.json), [full test log](../qa/release-0.6.3/tests-release.log), [native checkpoints](../qa/release-0.6.3/native/result.json), and screenshots retain the evidence. Production code was frozen at `d20ba4c0`. Final review fixes invalidate legacy motion indexes, retain lexical and canonical paths when moving projects, normalize background-open document IDs, and select a paintable layer when opening Raster files. The final acceptance harness requires fresh fixtures.
