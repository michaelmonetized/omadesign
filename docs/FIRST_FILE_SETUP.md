## File and machine preflight

Start with an existing Linux installation on aarch64/ARM64 or x86_64. The current
release targets glibc 2.35 or newer; your distribution and desktop still need to
pass the machine check. The completed hands-on proof used ARM64 Linux with
Omadesign 0.0.4-alpha, not every supported distribution or machine.

The candidate SVG should have one artboard, at most 20 simple path/shape objects,
four groups, and a file size of 5 MB or less. Use solid fills and ordinary strokes;
supply any text as outlines. No external images, linked fonts, scripts, animation,
filters, or complex masks. These are scope ceilings, not an automatic import
guarantee: we inspect the actual file and expected preview before accepting it.

This covers conversion and setup of existing artwork. Custom design, recoloring,
node editing, palettes, brand banks, batch migration, OS installation, dual boot,
driver repair, arbitrary Adobe/Affinity files, print-production color management,
and ongoing support are outside this offer. See the [format limits](format-support.md)
and [manual](MANUAL.md) for the app's broader capabilities and current limits.

## What has been checked

On September 8, 2026, an official release was installed on ARM64 Linux and used
with original synthetic SVG fixtures. The normal app imported three editable vectors, moved them,
saved the native document, exported a PNG, and reopened the edited `.oma`.
Separate CLI checks produced PNG, SVG, and PDF exports from a simple grouped
fixture. The GUI PNG matched a separate render of its saved document exactly.
These checks used test artwork, not a customer project or a completed paid order.

Omadesign is alpha. In the tested desktop, native file dialogs could show a
temporary responsiveness warning while waiting for input. Moving three selected
objects created three undo entries. SVG export/re-import could add wrapper
groups, so `.oma` remains the working master. The handoff includes the limitations
that apply to your accepted file.
